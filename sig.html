Le Système d'Information (SI)

📖 Définition — Système d'Information (SI)

Ensemble organisé de ressources (humaines, matérielles, logicielles et procédures) permettant de collecter, stocker, traiter et diffuser l'information au sein d'une organisation.

Les 4 composantes du SI

💾 Données
informations stockées
⚙️ Traitements
opérations sur données
👥 Acteurs
humains & machines
📋 Règles de gestion
procédures & contraintes
📖 SI vs Système informatique

Le système informatique désigne uniquement les équipements numériques (ordinateurs, logiciels, réseaux). Le SI est plus large : il inclut aussi les humains, procédures et règles qui gèrent l'information.

Finalités du SI

🎯 Les 3 finalités
  • Décisionnel — fournir des informations aux dirigeants pour prendre des décisions (tableaux de bord, reporting)
  • Opérationnel — gérer les opérations quotidiennes (commandes, factures, stocks, paie)
  • Communication — assurer les échanges internes (intranet) et externes (e-mail, site web)
🔑 À retenir — SI ouvert vs SI fermé
SI ouvert : connecté à l'extérieur (ERP, e-commerce, EDI)
SI fermé : usage interne uniquement (comptabilité interne, fichier RH local)

📝 Exercice 1 — Identifier les composantes d'un SI

Situation : La boulangerie Dupont emploie 3 vendeurs. Chaque vente est enregistrée sur une caisse enregistreuse reliée à un logiciel de gestion des stocks. Un tableau Excel hebdomadaire est envoyé par mail au comptable. La règle est : toute rupture de stock doit être signalée avant 18h.

Identifiez les données, les traitements, les acteurs et les règles de gestion du SI de cette boulangerie.
✅ Correction

Données : quantités vendues, prix, niveaux de stock, coordonnées fournisseurs

Traitements : enregistrement des ventes, mise à jour des stocks, génération du tableau Excel, envoi du mail

Acteurs : vendeurs (saisie), caisse enregistreuse, logiciel de gestion, comptable (réception)

Règles de gestion : toute rupture de stock signalée avant 18h ; envoi hebdomadaire du tableau au comptable

La modélisation des données (MCD / MLD)

📖 MCD — Modèle Conceptuel de Données

Représentation graphique des entités du monde réel et de leurs associations. Permet de modéliser la structure des données avant de créer une base de données.

Vocabulaire clé du MCD

📌 Concepts essentiels
  • Entité — objet du monde réel que l'on souhaite représenter (ex : CLIENT, COMMANDE, PRODUIT)
  • Propriété — caractéristique d'une entité (ex : nom, prénom, date_naissance)
  • Identifiant — propriété unique permettant d'identifier chaque occurrence (ex : id_client, num_commande). Souligné sur le MCD.
  • Association — lien sémantique entre entités (ex : un CLIENT passe une COMMANDE)
  • Occurrence — valeur concrète d'une entité (ex : le client n°42 Jean Dupont)

Les cardinalités

🔑 Lecture des cardinalités

Les cardinalités indiquent le minimum et le maximum d'associations possibles entre deux entités.

(0,1) = zéro ou un · (1,1) = exactement un · (1,n) = au moins un · (0,n) = zéro ou plusieurs

Méthode : On lit du côté de l'entité vers l'association : "Un CLIENT passe (0,n) commandes" = un client peut passer aucune ou plusieurs commandes.

Exemple de MCD — Commande client

Règles de passage MCD → MLD

🔑 Règles fondamentales

Règle 1 — Association (1,n) / (0,1) ou (1,1) :

La clé étrangère va dans la table du côté (1,1) ou (0,1)

Règle 2 — Association (n,n) :

Création d'une nouvelle table avec les deux identifiants comme clé primaire composite

MLD correspondant

🗂️ Modèle Logique de Données

CLIENT(id_client, nom, prenom, email)

COMMANDE(num_commande, date_commande, montant_total, #id_client)

→ #id_client = clé étrangère (association 1,n entre CLIENT et COMMANDE)

LIGNE_COMMANDE(#num_commande, #ref_produit, quantite)

PRODUIT(ref_produit, libelle, prix_unitaire)

→ Table créée pour l'association (n,n) "contient" entre COMMANDE et PRODUIT

📝 Exercice 2 — Créer un MCD et passer au MLD

Situation : Un club sportif gère des adhérents et des activités. Un adhérent peut s'inscrire à plusieurs activités. Une activité est animée par un seul moniteur. Un moniteur peut animer plusieurs activités.

1. Identifiez les entités et leurs propriétés.
2. Représentez le MCD avec les cardinalités.
3. Rédigez le MLD correspondant.
✅ Correction

1. Entités :

ADHÉRENT (id_adherent, nom, prenom, date_naissance) · ACTIVITÉ (id_activite, libelle, horaire) · MONITEUR (id_moniteur, nom, specialite)

2. MCD :

ADHÉRENT (0,n) — s'inscrit — (0,n) ACTIVITÉ

ACTIVITÉ (1,1) — animée par — (0,n) MONITEUR

3. MLD :

ADHERENT(id_adherent, nom, prenom, date_naissance)

MONITEUR(id_moniteur, nom, specialite)

ACTIVITE(id_activite, libelle, horaire, #id_moniteur)

INSCRIPTION(#id_adherent, #id_activite, date_inscription)

→ INSCRIPTION créée car (n,n) · #id_moniteur car (1,1) côté ACTIVITE

Les bases de données et SQL

📖 Base de données relationnelle

Ensemble de tables liées entre elles par des relations (clés étrangères). Gérée par un SGBD (Système de Gestion de Base de Données) comme MySQL, PostgreSQL, Oracle, Access ou SQL Server.

Le langage SQL

📖 SQL — Structured Query Language

Langage standard d'interrogation et de manipulation des bases de données relationnelles.

La requête SELECT

🔑 Structure complète d'une requête SELECT
SELECT colonnes FROM table WHERE condition ORDER BY colonne [ASC|DESC]
-- Exemple : clients dont le CA > 1000 € triés par nom SELECT nom, prenom, chiffre_affaires FROM client WHERE chiffre_affaires > 1000 ORDER BY nom ASC;

Les jointures

Jointure — relier deux tables
SELECT c.nom, c.prenom, co.num_commande, co.date_commande FROM client c JOIN commande co ON c.id_client = co.id_client WHERE co.date_commande > '2025-01-01';

Fonctions d'agrégation

🧮 Fonctions SQL essentielles
  • COUNT(*) — compte le nombre d'enregistrements
  • SUM(colonne) — somme des valeurs d'une colonne
  • AVG(colonne) — moyenne des valeurs
  • MAX(colonne) / MIN(colonne) — valeur max / min
  • GROUP BY — regroupe les résultats par valeur d'une colonne
  • HAVING — filtre appliqué après GROUP BY (comme WHERE mais sur agrégats)
-- Nombre de commandes et total par client SELECT c.nom, COUNT(co.num_commande) AS nb_commandes, SUM(co.montant_total) AS total_achats FROM client c JOIN commande co ON c.id_client = co.id_client GROUP BY c.id_client, c.nom HAVING COUNT(co.num_commande) > 3 ORDER BY total_achats DESC;

Modification des données

-- Insérer un client INSERT INTO client (nom, prenom, email) VALUES ('Martin', 'Sophie', 's.martin@mail.fr'); -- Modifier un client UPDATE client SET email = 'nouveau@mail.fr' WHERE id_client = 42; -- Supprimer un client DELETE FROM client WHERE id_client = 42;

📝 Exercice 3 — Requêtes SQL

Schéma : PRODUIT(ref_produit, libelle, prix_ht, categorie) · LIGNE_COMMANDE(#num_commande, #ref_produit, quantite)

1. Listez tous les produits de la catégorie "Informatique" triés par prix croissant.
2. Calculez la quantité totale vendue pour chaque produit.
3. Trouvez les produits dont la quantité totale vendue dépasse 50 unités.
✅ Correction
-- Question 1 SELECT libelle, prix_ht FROM produit WHERE categorie = 'Informatique' ORDER BY prix_ht ASC; -- Question 2 SELECT p.libelle, SUM(lc.quantite) AS total_vendu FROM produit p JOIN ligne_commande lc ON p.ref_produit = lc.ref_produit GROUP BY p.ref_produit, p.libelle; -- Question 3 SELECT p.libelle, SUM(lc.quantite) AS total_vendu FROM produit p JOIN ligne_commande lc ON p.ref_produit = lc.ref_produit GROUP BY p.ref_produit, p.libelle HAVING SUM(lc.quantite) > 50;

Les ERP et PGI

📖 ERP / PGI — Définition

ERP (Enterprise Resource Planning) = PGI (Progiciel de Gestion Intégré). Système logiciel intégré couvrant toutes les fonctions de l'entreprise (achats, ventes, production, comptabilité, RH) avec une base de données unique et partagée.

💡 Exemples d'ERP

SAP (grandes entreprises) · Oracle ERP · Sage (PME) · Microsoft Dynamics · Odoo (open source)

Avantages et inconvénients

✅ Avantages ❌ Inconvénients
Cohérence de l'information (données partagées)Coût élevé (achat, déploiement, formation)
Gain de productivité (automatisation)Rigidité (personnalisation limitée)
Traçabilité des opérationsDépendance à l'éditeur
Vue globale en temps réelConduite du changement complexe (résistance)
Interopérabilité entre servicesRisque de panne généralisée

📝 Exercice 4 — Justifier le choix d'un ERP

Cas : La société Techniparts (150 salariés, industrie) utilise actuellement 5 logiciels différents pour la comptabilité, les achats, la production, les ventes et les RH. Des doublons de données existent et la communication entre services est difficile.

Justifiez l'intérêt d'adopter un ERP pour Techniparts. Identifiez aussi deux risques à anticiper.
✅ Correction

Intérêts :

— Suppression des doublons : base unique partagée entre tous les services

— Meilleure communication inter-services : les données de production alimentent automatiquement les achats et la comptabilité

— Traçabilité améliorée et gain de temps (saisies uniques)

— Tableau de bord global en temps réel pour les dirigeants

Risques :

— Coût de mise en place élevé (licence + paramétrage + formation)

— Résistance au changement des salariés (conduite du changement à prévoir)

CRM et Business Intelligence

📖 CRM — Customer Relationship Management

Logiciel de gestion de la relation client centralisant l'historique des contacts, des achats, des réclamations et du SAV. Objectif : fidéliser les clients et personnaliser la relation.

📖 Business Intelligence (BI)

Ensemble des outils et méthodes permettant de collecter, analyser et visualiser les données de l'entreprise pour faciliter la prise de décision.

📌 Concepts clés de la BI
  • Data Warehouse — entrepôt de données historisées et agrégées provenant de différentes sources
  • Tableau de bord décisionnel — visualisation synthétique des KPI (indicateurs clés de performance)
  • KPI (Key Performance Indicator) — indicateur mesurable évaluant l'atteinte d'un objectif
  • OLAP (Online Analytical Processing) — traitement analytique multidimensionnel des données
  • Big Data — données massives caractérisées par les 3V : Volume (quantité), Vélocité (vitesse), Variété (types)

La sécurité du SI

🔑 DICP — Les 4 critères de sécurité
Disponibilité · Intégrité · Confidentialité · Preuve (traçabilité)

Disponibilité = le SI est accessible quand on en a besoin
Intégrité = les données ne sont pas altérées
Confidentialité = seules les personnes autorisées accèdent aux données
Preuve = les actions sont tracées et vérifiables (non-répudiation)

Menaces et mesures de protection

MenaceDescriptionMesure de protection
Virus / MalwareLogiciel malveillant altérant le SIAntivirus, mises à jour
RansomwareChiffre les données pour rançonSauvegardes régulières, PCA
PhishingUsurpation d'identité par mailFormation, filtre anti-spam
IntrusionAccès non autorisé au SIPare-feu, MFA, VPN
Perte de donnéesSuppression accidentelle ou pannePlan de sauvegarde (3-2-1)
⚠️ RGPD — Règlement Général sur la Protection des Données

Règlement européen en vigueur depuis mai 2018. Encadre la collecte et le traitement des données personnelles. Droits des personnes : accès, rectification, effacement (droit à l'oubli), portabilité, opposition. L'entreprise doit désigner un DPO (Délégué à la Protection des Données) si elle traite des données à grande échelle.

📌 Mesures techniques de sécurité
  • Pare-feu (firewall) — contrôle les flux réseau entrants et sortants
  • Chiffrement — rend les données illisibles sans clé (SSL/TLS, AES)
  • Authentification forte (MFA) — mot de passe + second facteur (SMS, appli)
  • Plan de Continuité d'Activité (PCA) — procédures pour maintenir l'activité en cas d'incident
  • Audit de sécurité — évaluation régulière des vulnérabilités

La modélisation des traitements

📖 Processus

Enchaînement d'activités organisées pour produire un résultat à partir d'un événement déclencheur. Ex : le processus "traiter une commande" est déclenché par la réception d'une commande client.

📌 Concepts essentiels
  • Événement déclencheur — fait qui initie le processus (ex : réception d'un bon de commande)
  • Résultat / livrable — sortie du processus (ex : commande livrée, facture émise)
  • Logigramme — représentation graphique du processus avec des formes standardisées (début, action, décision, fin)
  • Diagramme de flux — schéma montrant les échanges d'informations entre acteurs
  • Procédure — description détaillée et séquentielle des étapes d'un processus
  • Automatisation / RPA (Robotic Process Automation) — robots logiciels exécutant des tâches répétitives

Le projet SI et la transformation numérique

📖 Projet SI

Démarche structurée visant à mettre en place ou faire évoluer un système d'information. Comprend des phases : cadrage, conception, développement, tests, déploiement, maintenance.

MOA vs MOE

🏢 MOA — Maîtrise d'Ouvrage

Représente le client / donneur d'ordre. Exprime les besoins, valide les livrables. Rédige le cahier des charges fonctionnel.

⚙️ MOE — Maîtrise d'Oeuvre

Représente le réalisateur technique. Conçoit et développe la solution. Rédige le cahier des charges technique.

Méthodes de gestion de projet

MéthodeDescriptionAvantageLimite
Cascade (Waterfall) Phases séquentielles : analyse → conception → dev → test → livraison Simple, structuré Peu flexible aux changements
Agile (Scrum) Sprints courts (2-4 sem.), livraisons itératives, équipe auto-organisée Flexible, adaptatif Scope difficile à cadrer
Kanban Tableau visuel des tâches (À faire / En cours / Terminé) Visualisation, flux continu Moins structuré qu'Agile

Cloud computing

☁️ Modèles de service Cloud
  • IaaS (Infrastructure as a Service) — location de serveurs et infrastructure (ex : AWS, Azure)
  • PaaS (Platform as a Service) — plateforme de développement en ligne (ex : Google App Engine)
  • SaaS (Software as a Service) — logiciel accessible via internet (ex : Google Workspace, Salesforce)

Technologies de la transformation numérique

🚀 Technologies clés
  • Intelligence artificielle (IA) — automatisation intelligente, reconnaissance, prédiction
  • Blockchain — registre décentralisé, transparent et inaltérable (traçabilité, cryptomonnaies)
  • IoT (Internet des Objets) — objets connectés remontant des données en temps réel
  • Big Data & Data Science — analyse de volumes massifs de données pour décisions

📝 Exercice BAC — Analyser et proposer une évolution du SI

Type BAC

Cas : La chaîne de restaurants "FoodZen" (30 établissements) gère ses commandes par téléphone, ses stocks sur des fichiers Excel locaux et sa comptabilité avec un logiciel isolé. Les dirigeants souffrent d'un manque de vision globale, de doublons et d'une réactivité insuffisante face aux ruptures de stock.

1. Identifiez les dysfonctionnements du SI actuel de FoodZen.
2. Proposez une évolution du SI et justifiez vos choix technologiques.
3. Identifiez les risques de ce projet de transformation.
✅ Correction type BAC

1. Dysfonctionnements :

— SI fragmenté : 3 outils non interconnectés → incohérences de données

— Absence de vision globale : pas de tableau de bord consolidé pour les 30 restaurants

— Gestion des stocks inefficace : fichiers Excel locaux non synchronisés → ruptures non anticipées

— Prise de commandes manuelle (téléphone) → risque d'erreur et délais

2. Propositions d'évolution :

— Déployer un ERP en mode SaaS (ex : Odoo ou Sage) pour intégrer stocks, commandes et comptabilité

— Mettre en place un CRM pour centraliser la relation client et les commandes en ligne

— Installer un système de capteurs IoT sur les frigos pour anticiper les ruptures

— Créer un tableau de bord BI accessible en temps réel par la direction

3. Risques :

— Coût de déploiement et de formation élevé

— Résistance des employés au changement (conduite du changement à prévoir)

— Risque de panne généralisée si le SaaS est inaccessible (dépendance internet)

— Risque de sécurité et RGPD (données clients en ligne)
